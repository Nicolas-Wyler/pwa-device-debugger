# What the preview does and does not emulate

- Native macOS WKWebView, not an iOS Simulator. It preserves the configured CSS viewport but uses the host Mac's WebKit, fonts, GPU and audio stack. A real iPhone is still the authority.
- 2× engine backing density is requested without changing CSS width/height. Native ancestor-view scaling changes presentation only. A 1× monitor cannot physically show two pixels where it has one; higher-density surfaces are downsampled.
- The input firewall is injected at document start. It stops idle mouse pointer/hover events, forwards pressed gestures as touch-style PointerEvents, and removes `:hover` selectors from accessible stylesheets. It cannot guarantee access to cross-origin CSS rules or closed shadow-root styles.
- Synthetic PointerEvents are untrusted. A debug scroll shim pans scrollable ancestors while held when CSS touch-action permits it; this is not the browser’s native touch physics. Synthetic events do not implement multi-touch, pressure hardware, touch-only legacy APIs, or grant user-activation privileges. App code using PointerEvents can be tested; complex custom scrolling still needs validation on the real device. Do not mistake this for full device emulation.
- The host sets an iPhone user-agent and standalone indicators. It adapts accessible CSS `env(safe-area-inset-*)` rules to profile values and coarse-pointer media rules. It cannot replace the engine's actual CSS environment variables or every dynamically created stylesheet. `hover`, `pointer`, `screen` APIs and media-query combinations may still differ from iOS.
- URL mode loads the original site directly. Authentication, certificates, CORS, permissions and server behavior still apply. No proxy strips security policies. Local-directory mode supports static files, not application backends.
- WKWebView uses debugger-owned persistent storage; a stable localhost port is required to preserve the same origin across launches. This is not the browser profile or recovery state of an installed PWA. Service-worker/offline tests and install flows may differ from Safari/iOS. No iOS status-bar icons are fabricated. The bottom home indicator is a non-interactive visual dummy. The optional orientation-specific translucent keyboard image is a visual occlusion reference, not an implementation of the iOS keyboard or visualViewport resizing.
- The included geometry was derived from a photograph and constrained for symmetry. The numerical fit residual is not a certified hardware tolerance. Lens distortion, imperfect rectification, threshold selection and damaged glass can bias the trace.
- The current fitter is a single-notch, four-shared-corner model. Safe areas and other device shapes require deliberate profile editing.
- This repository contains no user photos, app source from the sampler, samples, credentials or browser-state exports. Output and build folders are ignored.
